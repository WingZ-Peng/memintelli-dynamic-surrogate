# Ideal-Conductance Dynamic Surrogate — Consolidated Summary

This directory is the standalone home of the current three-head surrogate.
It contains the architecture, the tuned configuration, the trained
checkpoints, and a full from-scratch verification run.

Generated by `scripts/write_summary.py` from the artifacts under
`outputs/three_head/`. Do not edit by hand; re-run the script instead.

## The question

For **one fixed weight and one fixed ideal conductance tensor `G_ideal`**,
can three conditional heads predict the `S_tile` output distribution that
*dynamic* read and voltage noise produces on held-out inputs?

The learned object is `p(Y | X, G_ideal, hardware_config)`. Write variation
and stuck faults are disabled — they are neither inputs nor part of the
target, so this is not a device-population model.

## Architecture

Three heads over the same 100 valid `S_tile` coordinates, all conditioned
on features that are deterministic functions of the input, `G_ideal`, the
layout and the hardware config — never of a realized `G_static`, a write
seed, or a stochastic trace.

| Head | Predicts | Parameterization | Features |
|---|---|---|---|
| Mean | residual `E[S] - nominal_S` | per-coordinate encoder + context pooling + fusion, zero-init output | 138 |
| Variance | clamped log-ratio vs a global per-coordinate variance | same architecture, different target | 138 |
| Correlation | full 100x100 correlation | factor model over the physical noise sources | 118 |

### The correlation head is the substantive change

An `S_tile` coordinate is `(k_block, row_index, out_index)`. It reads
voltages on its own row inside its own `k_block`, and conductance cells in
its own output column inside its own `k_block`. Two coordinates are
therefore functions of **disjoint** random variables unless they share a
`k_block` *and* (a row *or* an output column) — for every other pair the
covariance is exactly zero, by independence rather than by linearization.

Only 1,300 of the 9,900 off-diagonal entries can be non-zero. This run measures:

| Pair type | Pairs | RMS rho | Share of off-diagonal energy |
|---|---:|---:|---:|
| same k, shared row | 900 | 0.0760 | 7.4% |
| same k, shared output column | 400 | 0.3762 | 80.6% |
| same k, disjoint (exactly 0 in truth) | 3,600 | 0.0313 | 5.0% |
| different k_block (exactly 0 in truth) | 5,000 | 0.0312 | 6.9% |

The two rows that must be zero sit at RMS 0.0313 and 0.0312 against a pure-noise
prediction of 0.0221 — they carry only sampling noise.

Each coordinate is written as a unit-variance sum over those sources:

```text
S_d = <alpha_d, eps_voltage[k, row]> + <beta_d, eps_conductance[k, out]>
      + sqrt(1 - |alpha_d|^2 - |beta_d|^2) * eta_d
```

Properties that hold by construction rather than by fitting: coordinates
sharing no source are exactly uncorrelated; the matrix is positive
semi-definite for any parameter value; the diagonal is exactly one; and
sampling is native, with no Cholesky factorization.

`features.py` already stores the analytic loading as the unit-norm first 48
feature dimensions, so `[alpha ; beta]` has a closed-form value. The network
predicts only a bounded, zero-initialized correction to its direction plus a
per-coordinate explained-variance fraction — training *starts* at the
closed-form solution and is penalized for leaving it.

## Methodology

**Fail closed.** `configs/three_head_protocol.json` is hashed into a
`protocol_fingerprint` stamped on every shard, checkpoint and report. Any
artifact whose fingerprint disagrees is a hard error, never a silent
recompute. Shards are written atomically and carry a `checks` dict; the key
check is that the tail reconstruction reproduces the engine's own linear
output to 1e-5, which is what licenses the `S_tile`-space formulation.

**Model selection uses validation only.** The test split is read once, at
`analyze`. Head schedules and the correlation regularizer were chosen on
validation across multiple seeds.

**Three correlation metrics are reported.** The legacy full-matrix
Frobenius divides by a norm that includes the 100 unit diagonal entries,
compressing every score; it is kept for comparability. Off-diagonal-only
puts identity at exactly 1.0. Support-only scores the entries that can
physically be non-zero, and is the one that measures the model rather than
the reference's sampling noise.

**`exact_independent_split` is not a lower bound.** It is the distance
between *two noisy draws* of the same size, so a good deterministic
predictor can legitimately score below it. A floor ratio above 1.0 is not by
itself evidence of a bad head, and one below 1.0 is not an impossibility.

## Results from this run

256 train / 64 validation / 64 test contexts; 2,048 Exact samples per test context
split 1024 candidate / 1024 reference; 1,024 surrogate samples per context.

| Metric | Exact floor | Conditional | Shuffled features | Shared | Floor ratio |
|---|---:|---:|---:|---:|---:|
| Mean NRMSE | 0.0442 | **0.0335** | 0.1626 | 0.1164 | 0.759 |

| Correlation Fro. (support) | 0.1963 | **0.1429** | 1.3824 | 0.9895 | 0.728 |

`shuffled_input_features` rolls the features by one context, destroying the
conditioning while preserving the marginals; `shared` is the
context-independent predictor. Both are far worse than the conditional
heads, which is what shows the heads use the conditioning.

### Artifacts not in this repository

`outputs/three_head/context_shards/` holds about 254 MB of collected Exact
samples and is excluded. The `collect` stage regenerates it deterministically
from the protocol seeds, and the checkpoints and reports published here were
produced from exactly those shards.

## Dependencies

The `three_head` package imports only the standard library, `torch`, and
`memintelli.pimpy` — the frozen upstream device simulator. That simulator is
a third-party snapshot, vendored unmodified under
`memintelli_surrogate_comparison/upstream/` together with its license file,
and it is the only path the runner adds besides this directory. See the
repository README for attribution and a note on its licensing. No sibling
experiment folder is imported, and a test asserts this.

## What this does not show

- One fixed mathematical weight and ideal conductance tensor.
- Write variation and stuck faults are deliberately excluded.
- One fixed shape, tile layout, and hardware configuration.
- Synthetic Gaussian inputs, not real-network activations.
- Head schedules and the correlation regularizer were chosen on the validation split; the test split is read only here.
